# Інструкція із запуску AI-Генератора навчальних карток

Цей консольний застосунок використовує локальну мовну модель через Ollama для генерації навчальних карток (Flashcards) з тексту конспектів.

## 1. Вимоги
- Встановлена [Ollama](https://ollama.com/)
- Python 3.10 або новіший
- Бібліотека `openai`

## 2. Підготовка до запуску
1. Переконайтеся, що Ollama працює. Завантажте необхідну модель, виконавши в терміналі:
   ```bash
   ollama run qwen2.5:1.5b
   ```
2. Встановіть необхідну Python-бібліотеку:
   ```bash
   pip install openai
   ```

## 3. Запуск застосунку
1. Відкрийте термінал і перейдіть до папки із застосунком (`app`):
   ```bash
   cd app
   ```
2. Запустіть головний скрипт:
   ```bash
   python main.py
   ```
3. Вставте текст вашого конспекту у консоль та натисніть `Enter`. Застосунок автоматично проаналізує текст і виведе картки у форматі "Питання-Відповідь".
4. Для завершення роботи програми введіть `вихід`.

# Лабораторна робота №4. Локальний запуск і оптимізація моделей

*Відповіді на теоретичні питання (розділ 0) знаходяться у файлі `local_models_demo.ipynb`.*

## 1.1 Залізо
- **CPU:** Intel Core i5-11320H (4 ядра, 8 потоків, до 4.5 ГГц)
- **RAM:** 16 ГБ DDR4 3200 МГц (~8.0 ГБ доступно)
- **GPU:** Intel Iris Xe Graphics (інтегрована, використовує Shared GPU Memory до 7.9 ГБ)
- **Пропускна здатність пам'яті:** ~51.2 ГБ/с (DDR4-3200 у двоканальному режимі). Джерело: специфікації Intel та скріншоти Task Manager.

## 1.2 Розрахунок
- **Пам'ять:** Модель на 1.5B параметрів у 4-бітній квантизації вимагає ~1 ГБ VRAM (з урахуванням KV-кешу). Це легко поміщається у мої доступні 8 ГБ RAM.
- **Стеля швидкості:** `51.2 ГБ/с / ~0.75 ГБ (розмір ваг) = ~68 tok/s`. На практиці через накладні витрати інтегрованої графіки очікувана швидкість — 20-30 tok/s.

## 1.3 Обрана модель, квантизація й рантайм
- **Рантайм:** Ollama (зручний у встановленні, має OpenAI-сумісний API).
- **Модель:** `qwen2.5:1.5b` (Q4_K_M).
- **Чому:** Модель ідеально балансує між якістю української мови та швидкістю. Менша модель (0.5b) дає галюцинації, а більші (4b+) можуть викликати підкачку (swap) і сильні гальма.

## 1.4 Вимірювання до оптимізації
- **Модель:** `qwen2.5:1.5b`
- **Швидкість:** ~25.2 tok/s. TTFT: ~8.25с (для 2 клієнтів).
Це цілком комфортна швидкість для роботи, яка відповідає моїм розрахункам (з поправкою на втрати інтегрованого GPU).

## 1.5 Оптимізація і вимірювання після
- **Що змінено:** Спробував зменшити модель до `qwen2.5:0.5b`.
- **Результат після:** Швидкість зросла вдвічі до ~48-52 tok/s. TTFT впав до 4с.
- **Висновок:** Хоча швидкість значно зросла, якість тексту українською мовою у 0.5B помітно погіршилася. Для фінального застосунку я повернувся до **1.5B**, оскільки 25 tok/s є достатнім, а якість генерації карток критично важлива.

## 1.6 Застосунок
- **Назва:** AI-Генератор навчальних карток (Flashcards Maker).
- **Що робить:** Отримує текст конспекту та перетворює його на пари "Питання-Відповідь" для підготовки до іспитів.
- **Технології:** Python, бібліотека `openai` (для виклику локального API Ollama), стрімінг для плавності UI.
- **Параметри генерації:** `temperature=0.3` (для фокусу на фактах з тексту), `max_tokens=800` (щоб уникнути зациклення малої моделі, але згенерувати достатньо карток).

## 1.7 Тестові сценарії й результати
Було проведено тестування застосунку на 10 різних текстах (історія, програмування, фізика, мережі тощо). 

**Успішні сценарії:**
1. **Тест (Короткі факти):** Тексти про Київську Русь, Сонце, Атоми, TCP/UDP.
   *Результат:* Застосунок впорався ідеально, сформувавши чіткі пари "Питання-Відповідь", витягнувши саму суть.
2. **Тест (Списки/Переліки):** Текст про принципи ООП.
   *Результат:* Успішно. Модель коректно згрупувала всі 4 принципи в одну картку.

**Проблемні (крайові) випадки та помилки моделі:**
Оскільки використовується мала локальна модель (1.5B), на складніших текстах були виявлені такі проблеми:
1. **Втрата формату (Тест "Фотосинтез" та "Python"):** Замість однієї пари "Питання-Відповідь", модель почала генерувати нумеровані списки з багатьма питаннями, а для фотосинтезу взагалі забула згенерувати блок "Відповідь".
2. **Копіювання тексту (Тест "Перший закон Ньютона"):** Модель не змогла перефразувати текст і просто скопіювала його дослівно і в питання, і у відповідь.
3. **Мовна нестабільність (Тест "Трансформери"):** Незважаючи на український текст, модель згенерувала питання російською мовою (*"Какое механическое устройство используется..."*). Це типова проблема малих моделей через зміщення навчального датасету.

**Що я спробував зробити для виправлення:**
Щоб виправити втрату формату та мовну нестабільність, я додав у `system_prompt` більш жорсткі інструкції: 
*"Відповідай ТІЛЬКИ українською мовою. Формат відповіді має бути суворим: лише одне Питання і лише одна Відповідь."*
Це частково покращило ситуацію, але для повної стабільності (особливо утримання формату карток) системі потрібна більша модель (мінімум 7B-8B), яка, на жаль, буде занадто повільною на моєму "залізі". Тому поточний компроміс (qwen2.5:1.5b) є оптимальним.

## 1.8 Висновок
У ході лабораторної роботи я розрахував бюджет пам'яті для свого комп'ютера (без дискретної відеокарти, доступно ~8 ГБ RAM) та обрав оптимальну модель `qwen2.5:1.5b` (Q4_K_M). Вимірювання показали комфортну швидкість генерації ~25 tok/s. Спроба оптимізації через зменшення моделі до 0.5B дала приріст швидкості до ~50 tok/s, але критично знизила якість, тому для фінального застосунку (AI-Генератор навчальних карток) я залишив 1.5B. Застосунок успішно працює локально через OpenAI-сумісний API Ollama, генеруючи корисний навчальний контент, хоча іноді проявляє обмеження, притаманні малим LLM (втрата формату, мовні зсуви).
